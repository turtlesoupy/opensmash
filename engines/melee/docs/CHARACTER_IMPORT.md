# Importing created OpenSmash characters

The Melee web launcher supports pasting an owner-created source link from the
original OpenSmash character creator. Account linking is not required.

1. In the creator, open a completed character's download panel and choose
   **Copy Melee import URL**.
2. In the local Melee website, choose **Import character**, paste the URL, and
   choose Mario, Luigi, Captain Falcon, Fox, Marth, or Link's moveset.
3. Wait for download, integrity validation, and retargeting; then choose **Play as**.

Imported fighters show a small gear on their roster tile. It opens a manage
panel with **Play as** and **Remove from roster**; removal asks for a second tap,
then deletes the converted costume, retained source and portrait from this
computer through `DELETE /api/imports/<slug>`. The smash.fun creation is not
affected and can be imported again. Removal is refused while another import is
running, and bundled roster characters cannot be removed.

Imports persist in the local roster across server restarts. Reimporting identical
assets with the same name and target reuses the completed conversion. A different
target creates a separate roster entry. Closing the dialog does not cancel an
import; reopening it resumes progress while the server is still running.

The old `.osb6` bundle URL does not contain the original rigged source needed for
Melee. It produces an explanatory error. Older jobs without retained source
checkpoints cannot export yet; generating another game bundle cannot recover the
original mesh.

## Local development

Use the existing local setup and validated user ROM:

```sh
python3 tools/serve_melee.py
npm --prefix web run dev
```

Choose the ISO/GCM in the web boot screen. The server verifies the ROM before serving game assets. See [Boot and disc setup](BOOT_AND_DISC_SETUP.md). Python conversion dependencies and the
existing Melee build assets are required. Imported source/assets and costumes are
stored under `assets/characters/` and `build/characters/`; the private local roster,
portraits and conversion logs are under `build/character-imports/`.

Only source exports from `https://smash.fun` and `https://www.smash.fun` are accepted
by default. For a local source fixture, explicitly pass
`--import-origin http://127.0.0.1:8791`. Do not include this fixture setting in a
release. Assets must belong to the exact export, match declared SHA-256 hashes and
sizes, and pass mesh/image validation. Redirects and arbitrary asset URLs are
rejected.

## Creator change and release gates

The companion implementation is in `opensmash/pipeline/web-prototype`:
`server/source-export.js`, its routes in `server/index.js` and `fighter-jobs.js`,
and the button in `src/FighterJobModal.jsx`.

Export creation requires the signed-in job owner. The resulting unguessable link
grants access to the generated rigged mesh, portrait, stock/emblem art and announcer
audio. It does not expose source photos, prompts, costs or arbitrary checkpoint
files. Anyone holding the link can download those generated assets. Deleting the
job revokes the export route; existing downloaded copies remain local.

Before advertising the feature publicly:

- Ship the creator button and source-export routes together, then verify a real
  signed-in account's existing and newly generated characters against production
  storage. These changes have only been validated locally; live smash.fun has not
  been deployed by this task.
- Include the local conversion server and its dependencies in the intended web
  distribution. A static web upload alone does not provide this importer. Native
  picker import integration is a separate task.
- Smoke-test imports and gameplay on each supported release platform. This pass
  validates the local macOS browser path, not Windows/Linux packaging or mobile
  gameplay. Experimental non-humanoid targets are not exposed for arbitrary imports.

## Validation (2026-09-10)

A local manifest generated by the actual creator export module was served over
HTTP and imported using Alan Turing's original rigged source. The full costume,
presentation and browser-skin conversion completed. Pasting that link into the
browser returned the existing conversion, added the fighter to the roster, and
**Play as** launched a live match against Mario. The on-screen counter read
approximately 60 FPS (61 in the captured frame); this is a smoke check, not a
cross-platform performance benchmark.

The Melee suite passed 58 tests; the creator export/protocol suite passed 6 tests.
Both web production builds passed. Tests cover owner checks, export whitelisting,
manifest hashes, URL restrictions, source round-trip and presentation metadata.
